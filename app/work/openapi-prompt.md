# coffee shop client requirements 

## Summary 

The client will use retrofit and moshi with the okhttp loging interseptor to build an interface to consume the service defined in the server sub-project.

## Generation 

- The open api generator must generate a kotlin proxy interfaces and kotlin dataclass dtos.

- The generator must not generate excessive additional classes; In particular convertors and adapters generated by the generator will not be used by the client code, but will be developed separately.

- Generator configuration properties should be located in @gradle.properties at the app level or in another suitable properties file; if it is cleaner to create a separate properties file just for generation properties, that is acceptable.

- If satisfying the above requirements dictates the separation of generation into multiple gradle tasks that is acceptable.

- The generated proxy interfaces should use kotlin coroutines; These will be implemented using suspend functions.

- Generated dto classes must have the "Dto" suffix.

- If possible the build configuration must be adjusted so that moshi annotations on dataclass constructor parameters are applied to both the parameter and the property.

## Authentication 

- An okhttp interceptor must be used to add `Authorization` headers to all requests. 

## Repositories 

- All repositories that implement the generated proxy interfaces must use kotlin coroutines and convert between dtos and domain classes.
